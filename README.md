**БАР** — self-hosted open-source инструмент для сравнения страницы с
конкурентами из поисковой выдачи. Он анализирует нормализованные термы, N-граммы, HTML-зоны,
распределение терминов, облака слов, объём текста и опциональные семантические
эмбеддинги фраз.

Проект сделан в школе [SEO Мясо](https://seomeat.ru/). Создатель —
[Максим Котенков](https://t.me/seokotenkov).

> Статус: **pre-release**. БАР подходит для локальной работы и самостоятельного
> развёртывания. Перед публикацией общего сервера настройте авторизацию, лимиты,
> бюджет платных API, безопасное хранение секретов и мониторинг.

<summary>English summary</summary>

BAR is a self-hosted open-source relevance analyzer for comparing a page with
organic-search competitors. The main report does not require Python or an
external LLM. XMLRiver and Firecrawl are bring-your-own-key integrations. The
optional local E5 service improves multilingual N-gram-to-key similarity.

## Возможности

- поиск конкурентов через XMLRiver без фиксированного лимита в интерфейсе;
- обычная HTTP-загрузка страниц с Firecrawl fallback только после ошибки или
  обнаружения антибот-заглушки;
- фильтрация плохо загруженных страниц и аномально бедного контента;
- анализ термов и N-грамм по зонам `Title`, `H1`, `H2–H6`, основному тексту и
  ссылкам;
- сравнение своей страницы, медианы и каждого конкурента;
- три метрики страницы: TF-IDF ключей, взвешенный охват и взвешенная плотность;
- стоп-слова, стоп-фразы и предустановленный список шумовых терминов;
- графики распределения, таблицы и три синхронных облака слов;
- пересчёт ключей и стоп-термов по сохранённому корпусу без повторной загрузки;
- мультиязычное сходство N-грамм с ключами через локальный E5-сервис;
- нормированные под объём своей зоны ориентиры и позиционная вложенность фраз;
- готовое ТЗ для страницы в Markdown, сгруппированное по HTML-зонам.

Основной отчёт работает без Python, Docker, Firecrawl и E5.
Без E5 используется встроенный детерминированный алгоритм; недоступность
дополнительных NLP-сервисов не ломает отчёт.

## Быстрый старт

### 1. Получите проект

```bash
git clone https://github.com/mekotenkov-ux/bar-relevance-analyzer.git
cd bar-relevance-analyzer
npm ci
```

Без Git можно выбрать **Code → Download ZIP** на странице репозитория,
распаковать архив и открыть терминал в папке с `package.json`.

### 2. Создайте локальную конфигурацию

Windows PowerShell:

```powershell
Copy-Item env.example .dev.vars
```

Linux или macOS:

```bash
cp env.example .dev.vars
```

`.dev.vars` уже исключён из Git. Шаблон настроен на локальный
`SITE_URL=http://localhost:3000`. Для первого запуска другие значения можно не
заполнять: данные XMLRiver разрешено ввести прямо в интерфейсе, а Firecrawl и
E5 оставить выключенными.

### 3. Запустите БАР

```bash
npm run dev
```

Откройте адрес, который напечатал сервер. Обычно это
<http://localhost:3000/analyzer>. Для остановки нажмите `Ctrl+C`.

## Первый анализ

1. Откройте `/analyzer`.
2. В карточке **XMLRiver — обязательный источник выдачи** введите свой ID и
   ключ либо заранее настройте их на сервере.
3. Укажите запрос и поисковую систему, сначала выберите страну, затем город или
   регион внутри неё, и задайте нужное количество конкурентов.
4. Вставьте URL своей страницы или переключитесь в режим **Вставить текст**.
5. Нажмите **Найти и проанализировать**.

XMLRiver credentials, введённые в интерфейсе, хранятся только в
`sessionStorage` текущей вкладки. На общем компьютере после работы закройте
вкладку целиком.

## Языки, словоформы и стоп-слова

Русский язык выбран в новой форме анализа по умолчанию. Внутри БАР режимы
нормализации различаются явно:

- для `ru` применяется словарный морфологический анализ **Az.Morph** на основе
  OpenCorpora: словоформы приводятся к нормальной форме, а не обрезаются по
  окончанию;
- для `ar`, `hy`, `eu`, `ca`, `cs`, `da`, `nl`, `en`, `fi`, `fr`, `de`,
  `hu`, `ga`, `it`, `no`, `pt`, `ro`, `sl`, `es`, `sv`, `ta`, `tr`
  применяется **Snowball stemming**. Он склеивает многие формы по окончанию,
  но стем не всегда равен лингвистической лемме;
- для `bg`, `zh`, `hr`, `et`, `el`, `he`, `hi`, `id`, `ja`, `ko`,
  `lv`, `lt`, `fa`, `pl`, `sr`, `sk`, `sw`, `th`, `uk`, `ur`, `vi`
  используются **Intl.Segmenter и нормализованные словоформы**.
  Разные окончания там остаются отдельными термами.

N-граммы строятся из тех же термов внутри границ предложения. Для русского их
составные слова нормализуются морфологически; для режима без морфологии варианты
N-грамм с разными окончаниями не склеиваются.

Для всех языков, кроме сербского и тамильского, есть встроенный локализованный
стоп-лист. Он применяется на сервере автоматически. Редактируемые дополнительные
пресеты для русского, английского и испанского хранятся в
[`lib/default-stop-terms.ts`](lib/default-stop-terms.ts). При переключении языка интерфейс хранит
отдельный черновик пользовательских стоп-термов для каждого языка.

Автоопределение сначала учитывает `html lang`, затем доминирующую письменность,
характерные буквы и локальные стоп-слова. Кириллическая группа различает
русский, украинский, болгарский и сербский, а арабская — арабский, персидский и
урду. Для близких языков одной письменности без корректного `html lang`
(особенно сербского и хорватского на латинице) надёжнее выбрать язык вручную.

Многословные элементы встроенных локализованных стоп-листов сопоставляются как
последовательности слов. Они не превращаются в фиктивное «одно слово», а их
леммы-компоненты остаются доступны в таблице по тем же правилам, что и для
пользовательских стоп-фраз.

### Как добавить ещё один язык

1. Добавьте код и название в единый реестр
   [`lib/language-support.ts`](lib/language-support.ts).
2. Подключите проверяемую словарную морфологию (`lemmatization`), выберите реально
   доступный Snowball-алгоритм (`stemming`) или оставьте `tokens` без обещания
   склейки словоформ.
3. При наличии списка в пакете `stopword` укажите его export. Если export
   нет, UI должен честно показывать, что стоп-слова нужно задать вручную.
4. При необходимости добавьте консервативный редактируемый пресет в
   [`lib/default-stop-terms.ts`](lib/default-stop-terms.ts). Не помещайте многословную
   фразу в `words`: она должна быть в `phrases`.
5. Расширьте автоопределение, если язык не имеет уникальной письменности.
6. Добавьте тесты на токенизацию, словоформы, N-граммы и стоп-слова по образцу
   [`tests/multilingual-v13.test.mjs`](tests/multilingual-v13.test.mjs), затем запустите `npm run check`.

Новый словарный лемматизатор должен быть детерминированным, иметь регрессионные
фикстуры и учитывать совместимость snapshot.

## Как читать отчёт

- В верхней сводке первые три карточки показывают результат нашей страницы в
  формате **«значение из среднего по конкурентам»**. Например, `64% из 71%`
  означает, что наша страница набрала `64%`, а среднее среди принятых
  конкурентов — `71%`. Для объёма текста по-прежнему показывается более
  устойчивый ориентир — медиана конкурентов.
- Значок `?`, наведение на важные элементы и фокус с клавиатуры открывают
  краткие подсказки. Заголовки колонок одновременно объясняют показатель и
  сортируют таблицу по клику.
- **Важность леммы** — нормированная оценка `0–100`, которая учитывает TF-IDF,
  число документов с леммой и подтверждение в ключах и заголовках.
  **Важность N-граммы** также учитывает распространённость фразы у конкурентов,
  смысловую связь с ключами и подтверждение в ключе и Title/H1–H6. Точные
  коэффициенты в интерфейсе не публикуются.
- **Ориентиры вхождений** рассчитываются по плотности у конкурентов и
  автоматически приводятся к объёму нашей страницы или выбранной HTML-зоны.
  Если наша зона вдвое короче типичной зоны конкурентов, рекомендуемое число
  вхождений также уменьшается примерно вдвое. Любой видимый ориентир остаётся
  целым и не бывает меньше `1`.
- Значение внутри показанного диапазона считается выполненным и не попадает в
  действие **Добавить** или в итоговое ТЗ.
- Короткая фраза объединяется с длинной только при позиционном доказательстве,
  что все её вхождения находятся внутри одной конкретной длинной фразы.
  Самостоятельные и неоднозначно вложенные употребления сохраняются отдельно.
- В N-граммах отметка **Ключ** означает точное совпадение с входным ключом, а
  **Возможно ключ** — неточное смысловое сходство выше `0,8`.
- Заголовки всех аналитических таблиц сортируются кликом. Внизу отчёта БАР
  формирует копируемое Markdown-ТЗ по зонам: сначала фразы, затем леммы.

## Конфигурация

Безопасный пример всех переменных находится в [`env.example`](env.example).

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `SITE_URL` | для публикации | Доверенный канонический origin, например `https://bar.example.com`. |
| `XMLRIVER_USER` | нет | Серверный ID XMLRiver. |
| `XMLRIVER_KEY` | нет | Серверный ключ XMLRiver. |
| `FIRECRAWL_API_KEY` | нет | Firecrawl fallback для недоступных URL и заглушек. |
| `PHRASE_EMBEDDINGS_URL` | нет | Локальный E5-сервис; обычно `http://127.0.0.1:8093`. |
| `PHRASE_EMBEDDINGS_TIMEOUT_MS` | нет | Таймаут пакетного расчёта сходства N-грамм. |
| `PHRASE_EMBEDDINGS_CHUNK_SIZE` | нет | Число N-грамм в одном запросе к E5. |

Для `npm run dev` используйте игнорируемый `.dev.vars`. При `npm start`
передавайте значения через `process.env`, secret manager либо локальный
игнорируемый `.env.production.local`.

Не добавляйте реальные ключи в `env.example`, исходный код, Docker-образы,
логи, issues, pull requests или build artifacts.

### XMLRiver

XMLRiver обязателен для запуска БАР. Есть два режима подключения:

- **BYOK в браузере** — оставьте `XMLRIVER_USER` и `XMLRIVER_KEY` пустыми и
  введите credentials в интерфейсе. Это рекомендуемый вариант для локальной
  работы.
- **Серверный ключ** — заполните переменные и перезапустите приложение. На
  публичном сервере посетители смогут расходовать этот ключ через backend,
  поэтому обязательны авторизация, квоты, rate limiting и бюджет.

Для обратной совместимости поддерживается `XMLRIVER=user:key`, но две отдельные
переменные понятнее и безопаснее обслуживать.

Страна и регион выбираются отдельно. Сначала БАР загружает список стран для
выбранной поисковой системы, а затем ищет города и регионы только внутри
выбранной страны. В поле региона можно выбрать и всю страну. Итоговое значение
остаётся однозначным и содержит точный ID, например `Москва, Россия — 213`.
Офлайн-snapshot от 26 августа
2026 года содержит все 99 819 строк официального Google geo.csv (99 817 со
статусом `Active`) и все 708 уникальных кодов опубликованного XMLRiver списка
Яндекса. Для популярных Google-регионов сохранены русские названия и алиасы;
остальные отображаются под официальными названиями и полными canonical names.
Приложение не загружает справочники во время работы. Также можно указать любой
официальный числовой ID, даже если его ещё нет в snapshot. Источники —
[документация Яндекса XMLRiver](https://xmlriver.com/apiydoc/apiy-about/),
[иерархический список регионов Яндекса](https://xmlriver.com/blog/spisok-kodov-regionov-yandex-poiska-s-ierarhiej.html),
[документация Google XMLRiver](https://xmlriver.com/apidoc/api-about/) и
[полный Google geo.csv](https://xmlriver.com/files/geo.csv). Встроенный API
подсказок поддерживает список стран
`/api/xmlriver-regions?engine=yandex&countries=1` и фильтрацию
`/api/xmlriver-regions?engine=yandex&countryCode=RU&q=моск`. Старые запросы без
страны и сохранённый формат `Москва — 213` продолжают работать.

Ссылки «Подключить XMLRiver» и «Подключить Firecrawl» показываются только для
неподключённой интеграции. При успешном подключении остаётся компактный статус.

### [Firecrawl](https://www.firecrawl.dev/)

Добавьте ключ и перезапустите приложение:

```dotenv
FIRECRAWL_API_KEY=ваш_ключ
```

БАР всегда сначала выполняет обычный HTTP-запрос. Если ключ настроен, Firecrawl
автоматически вызывается только после ошибки либо обнаружения низкокачественной
антибот-страницы. Переключателя в интерфейсе нет: наличие серверного ключа само
включает fallback, а его отсутствие сохраняет обычную HTTP-загрузку.

При fallback-загрузке URL и содержимое страницы обрабатываются сторонним
сервисом Firecrawl. Наличие ключа не гарантирует обход любой защиты: плохая
заглушка всё равно будет исключена из анализа. Однако fallback может заметно
увеличить долю успешно разобранных страниц конкурентов.

## Сходство N-грамм через E5

БАР умеет сравнивать N-граммы с входными ключами локальной мультиязычной моделью
[`intfloat/multilingual-e5-large-instruct`](https://huggingface.co/intfloat/multilingual-e5-large-instruct).
E5 применяется только к сходству фраз: три метрики страниц и расчёт лемм от него
не зависят. Распространённость фразы у конкурентов остаётся отдельным сигналом,
поэтому редкая тематическая ошибка модели не обязана попадать в верх отчёта.

Запуск через Docker:

```bash
docker compose -f services/phrase-embeddings/docker-compose.yml up --build -d
```

Либо нативно на Python 3.12:

```powershell
py -3.12 -m venv services/phrase-embeddings/.venv
services\phrase-embeddings\.venv\Scripts\python.exe -m pip install -r services/phrase-embeddings/requirements.txt
node services/phrase-embeddings/start.mjs
```

Подключите готовый сервис к web-приложению через игнорируемый `.dev.vars`:

```dotenv
PHRASE_EMBEDDINGS_URL=http://127.0.0.1:8093
PHRASE_EMBEDDINGS_TIMEOUT_MS=300000
PHRASE_EMBEDDINGS_CHUNK_SIZE=512
```

Первый запуск скачивает около 1,1 ГБ весов в `work/hf-cache` и выполняет короткий
warm-up. Проверка готовности — `GET http://127.0.0.1:8093/healthz`. Результаты E5
сохраняются в snapshot вместе с моделью и revision: повторный пересчёт тех же
ключей не обращается к сервису. Старые snapshot и другой набор ключей безопасно
используют встроенный fallback. Полный контракт, Docker-настройки и живой
diagnostic описаны в [`services/phrase-embeddings/README.md`](services/phrase-embeddings/README.md).

## Production self-hosting

Для локальной проверки production-режима создайте конфигурацию до сборки.

Windows PowerShell:

```powershell
Copy-Item env.example .env.production.local
```

Linux или macOS:

```bash
cp env.example .env.production.local
```

Укажите корректный `SITE_URL` и необходимые server-side переменные, затем:

```bash
npm ci
npm run build
npm start
```

На реальном хостинге используйте переменные окружения или secret manager, а не
файлы с ключами. Приложению нужен исходящий HTTPS-доступ к XMLRiver, Firecrawl и
анализируемым страницам.

Перед открытием общего доступа:

1. включите HTTPS и авторизацию;
2. ограничьте частоту, параллелизм, длительность и размер запросов к `/api/*`;
3. задайте квоты, дневной бюджет и аварийное отключение платных API;
4. проверьте максимальный корпус на лимитах памяти и времени платформы;
5. добавьте request ID, безопасные структурированные логи и мониторинг ошибок;
6. при использовании E5 оставьте его в loopback/приватной сети;
7. не публикуйте служебные порты и локальные env-файлы.

## Данные и безопасность

- Backend по умолчанию stateless: отчёт и snapshot возвращаются в браузер.
- Интерфейс пытается сохранить текущий отчёт в `sessionStorage`. Большой отчёт
  может не сохраниться при исчерпании браузерной квоты.
- При пересчёте ключей используется сохранённый корпус без повторной загрузки
  страниц.
- XMLRiver получает поисковый запрос; Firecrawl получает URL и содержимое только
  fallback-страниц.
- Анализируемые URL, HTML, redirects, API-ответы и snapshots считаются
  недоверенным вводом.

Никогда не коммитьте `.env*`, `.dev.vars*`, credentials, API-ключи, токены или
приватное содержимое анализируемых страниц. Если ключ попал в commit, artifact,
лог или скриншот, немедленно отзовите его у провайдера и создайте новый.

О проблемах безопасности сообщайте по инструкции в [SECURITY.md](SECURITY.md).

### Правила для AI-агентов

Если проект изменяет кодовый агент, он обязан:

1. **Не читать и не выводить секреты.** Запрещено открывать, парсить, печатать,
   логировать или передавать в контекст содержимое `.env`, `.env.*`,
   `.dev.vars` и `.dev.vars.*`. Имена переменных брать только из
   `env.example`.
2. **Не менять аналитику побочным эффектом.** Формулы, пороги, округление,
   нормализацию и смысл метрик менять только по явной продуктовой задаче и вместе
   с регрессионными тестами.
3. **Сохранять детерминизм.** Одинаковый корпус и snapshot должны давать
   одинаковые значения и порядок строк.
4. **Считать внешние данные недоверенными.** Не ослаблять защиту URL, redirect,
   локальных/metadata-адресов, входных размеров и SSRF без отдельного security
   review.
5. **Не повторно загружать корпус.** Пересчёт ключей и стоп-термов
   выполняется только из snapshot v5, сохраняет `snapshot.id` и не вызывает
   XMLRiver, обычную загрузку страниц или Firecrawl.

Инварианты аналитики:

- термы, леммы и N-граммы с количеством меньше `1` в отчёт не попадают;
- отображаемые вхождения целые, «У нас» и «Ориентир» округляются вверх;
- косинусное сходство применяется только к похожести N-грамм на ключи, но не как
  оценка сайта;
- TF-IDF ключей, взвешенный охват и взвешенная плотность остаются тремя
  отдельными метриками;
- стоп-слово исключает соответствующий стем или словоформу и все фразы с ней,
  стоп-фраза — совпадающую последовательность;
- зональный анализ согласован для `all`, `title`, `h1`, `text`, `h2-h6` и `a`;
- недоступность необязательного E5 не должна ломать основной отчёт.

Перед pull request агент или разработчик должен:

1. проверить `git status` и исключить секреты, кеши, модели, env-файлы и artifacts;
2. добавить регрессионный тест для каждого изменения поведения;
3. синхронно обновить UI-справку, README и `CHANGELOG.md`, если изменился
   пользовательский смысл;
4. выполнить `npm run check`;
5. для изменений E5 выполнить релевантный diagnostic из README сервиса;
6. сохранить стандартную MIT-лицензию и корректные credits upstream-проекта.

## Частые проблемы

<details>
<summary><code>node</code>, <code>npm</code> или PowerShell не запускаются</summary>

Установите Node.js `>=22.13.0`, закройте все окна терминала и откройте новое.

Если PowerShell блокирует `npm.ps1`, не меняйте системную политику: используйте
`npm.cmd`.

```powershell
npm.cmd ci
npm.cmd run dev
```

</details>

<details>
<summary>Порт веб-приложения занят</summary>

```bash
npm run dev -- --port 3001
```

Откройте <http://localhost:3001/analyzer>. Если используется `SITE_URL`, укажите
тот же origin.

</details>

<details>
<summary>XMLRiver или Firecrawl не подключается</summary>

- проверьте ID, ключ, баланс, разрешения и случайные пробелы;
- перезапустите приложение после изменения `.dev.vars`;
- для XMLRiver попробуйте BYOK-ввод через интерфейс;
- для Firecrawl проверьте точное имя `FIRECRAWL_API_KEY`;
- откройте `/api/search-competitors`: ответ показывает только
  `serverConfigured` и `firecrawlConfigured`, не раскрывая секреты;
- проверьте исходящий HTTPS-доступ.

</details>

<details>
<summary>Анализ долгий или не хватает памяти</summary>

- временно уменьшите количество конкурентов;
- временно отключите E5, если CPU-сервис перегружен;
- не запускайте много тяжёлых отчётов одновременно;
- проверьте доступную память Docker и исходящие сетевые запросы;
- для serverless-платформ проверьте лимиты времени, памяти и размера ответа.

</details>
