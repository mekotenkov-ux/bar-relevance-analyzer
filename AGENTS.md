# Инструкция для кодовых агентов

## Назначение проекта

**БАР — бесплатный анализ релевантности** — open-source веб-инструмент школы
[SEO Мясо](https://seomeat.ru/) для сравнения страницы с конкурентами по леммам,
N-граммам, HTML-зонам и семантическим связям. Создатель проекта — Максим Котенков:
[Telegram](https://t.me/seokotenkov).

Основной отчёт должен работать без Python, Firecrawl и LLM. Firecrawl является
только опциональным fallback для страниц, которые не удалось качественно получить
обычным HTTP-запросом. Семантические связи — отдельная опция на spaCy и не должны
мешать формированию основного отчёта при ошибке или недоступности сервиса.

## Критическое правило: секреты

- Никогда не открывайте, не читайте, не парсите, не печатайте, не логируйте и не
  передавайте в контекст содержимое `.env`, `.env.*`, `.dev.vars` или
  `.dev.vars.*`. Допустимо только проверить существование такого файла без чтения.
- Никогда не выводите значения переменных окружения, API-ключей, токенов,
  credentials или заголовков авторизации — даже частично, в замаскированном виде
  или для диагностики.
- Никогда не добавляйте эти файлы и значения в Git, patch, issue, PR, тестовый
  fixture, snapshot, лог, Docker image или build artifact.
- Имена и безопасные примеры переменных берите только из отслеживаемого
  `env.example`. Реальные значения вводит оператор локально или через secret
  manager целевой платформы.
- Перед PR проверьте список изменённых и неотслеживаемых файлов. Если секрет мог
  попасть в историю или artifact, остановитесь, не публикуйте его и сообщите
  владельцу о необходимости отозвать и заменить ключ.

## Bootstrap Node.js

Требуется Node.js `>=22.13.0` и поставляемый с ним npm. Для запуска самого
приложения Python необязателен; для полного `npm run check` нужен доступный
интерпретатор `python` (без обязательной установки spaCy).

Для новой рабочей копии:

```bash
git clone https://github.com/mekotenkov-ux/bar-relevance-analyzer.git
cd bar-relevance-analyzer
```

```bash
npm ci
```

Создайте локальную runtime-конфигурацию из публичного шаблона, не просматривая и
не заполняя её автоматически:

```bash
cp env.example .dev.vars
```

PowerShell:

```powershell
Copy-Item env.example .dev.vars
```

Файл `.dev.vars` игнорируется Git и используется при `npm run dev`. Для
`npm start` значения должны приходить из `process.env`, secret manager либо
игнорируемого `.env.production.local`. Для базового запуска внешние сервисы не
обязательны; XMLRiver можно подключить собственными данными через интерфейс.

Основные команды:

```bash
npm run dev
npm run check
npm run build
npm run start
```

- `npm run dev` — локальная разработка;
- `npm run check` — typecheck, lint, production build, Node.js-тесты и проверка
  синтаксиса Python; требует команду `python`, но не установленный spaCy;
- `npm run build` — production-сборка;
- `npm run start` — запуск уже собранного production-приложения; перед ним
  обязательно выполните `npm run build`.

Не заменяйте `npm ci` на плавающую установку зависимостей. Если зависимость
изменена осознанно, синхронно обновите `package.json` и `package-lock.json`.

## Опциональный spaCy

Рабочие модели связей зафиксированы для русского и английского языков. Для
нативного запуска рекомендуется Python 3.12 и отдельное окружение.

Windows:

```powershell
py -3.12 -m venv services/triplets-symbolic/.venv
services\triplets-symbolic\.venv\Scripts\python.exe -m pip install -r services/triplets-symbolic/requirements-spacy.txt
node services/triplets-symbolic/start.mjs
```

Linux/macOS:

```bash
python3.12 -m venv services/triplets-symbolic/.venv
services/triplets-symbolic/.venv/bin/python -m pip install -r services/triplets-symbolic/requirements-spacy.txt
node services/triplets-symbolic/start.mjs
```

Кроссплатформенный запуск через Docker:

```bash
docker compose -f services/triplets-symbolic/docker-compose.yml up --build
```

Проверка готовности:

```bash
curl http://127.0.0.1:8092/healthz
```

В корневом `.dev.vars` оператор настраивает `TRIPLET_ENGINE=spacy` и
`TRIPLET_SPACY_URL=http://127.0.0.1:8092` по примеру из `env.example`. Агент не
должен читать получившийся файл. Не публикуйте встроенный spaCy HTTP-сервис в
интернет: он рассчитан на loopback и не имеет собственной аутентификации.

## Карта архитектуры

- `app/analyzer/page.tsx` и `app/analyzer/analyzer.module.css` — форма, состояние
  анализа и интерактивный отчёт;
- `app/api/search-competitors/route.ts` — поиск конкурентов;
- `app/api/analyze-run/route.ts` — основной анализ;
- `app/api/analyze-triplets/route.ts` — отдельный запуск семантических связей;
- `lib/semantic-analysis.ts` — загрузка и очистка страниц, лемматизация,
  N-граммы, зональные метрики, формулы отчёта и построение snapshot;
- `lib/semantic-triplets.ts` — подготовка сохранённого корпуса к этапу связей;
- `lib/deterministic-triplets-contract.ts` и `lib/triplet-symbolic.ts` — контракт
  и нормализация детерминированных связей;
- `lib/default-stop-terms.ts` — предустановленные стоп-слова и стоп-фразы;
- `lib/cloud-layout.ts` — детерминированная раскладка облаков;
- `services/triplets-symbolic` — локальный spaCy backend RU/EN;
- `services/triplets` и `experiments/triplets-llm` — архивный LLM-эксперимент,
  не являющийся production-путём по умолчанию;
- `tests` — контрактные и регрессионные тесты интерфейса и аналитики;
- `docs/ARCHITECTURE.md` и `docs/deterministic-triplets-contract.md` — границы
  компонентов и подробные инварианты.

URL, HTML, ответы XMLRiver/Firecrawl и переданный браузером snapshot всегда
считайте недоверенными данными. Не ослабляйте ограничения протокола, redirect,
размера входа/ответа или защиту локальных и metadata-адресов без отдельного
security review и тестов.

## Правила изменения аналитики

- Не меняйте формулы, коэффициенты, нормализацию, округление, пороги, фильтрацию
  или смысл пользовательской метрики как побочный эффект другой задачи.
- До изменения зафиксируйте текущую семантику тестом, затем добавьте fixture с
  ожидаемым поведением и только после этого меняйте реализацию.
- Расчёт должен оставаться детерминированным. Одинаковые входы и snapshot должны
  давать одинаковые значения и порядок строк, кроме явно временных метаданных.
- Количество вхождений, показываемое пользователю, остаётся целым; рекомендуемые
  значения «У нас» и «Ориентир» округляются вверх. Термы, леммы и N-граммы с
  количеством меньше `1` в отчёт не попадают.
- Косинусное сходство разрешено только для поиска фраз, похожих на ключи. Оно не
  является самостоятельной оценкой релевантности сайта.
- Итоговые метрики сайта сохраняют три разных смысла: оценка TF-IDF ключей,
  взвешенный штучный охват важных лемм/фраз и взвешенная плотность относительно
  ориентира каждого терма. Не объединяйте и не переименовывайте их без явной
  продуктовой задачи.
- Стоп-слово исключает соответствующую лемму и все фразы с ней; стоп-фраза
  исключает совпадающую фразу. Поведение должно сохраняться при пересчёте из
  snapshot.
- Зональный анализ должен согласованно переключать таблицу и график для `all`,
  `title`, `h1`, `text`, `h2-h6` и `a`.
- Если меняется формула или её пользовательский смысл, синхронно обновите справку
  интерфейса, README/документацию и `CHANGELOG.md`. Не публикуйте внутренние
  коэффициенты в UI, если задача явно этого не требует.

Минимально обязательные регрессии для изменений аналитики:

- `tests/semantic-v3.test.mjs` и `tests/lemma-v4.test.mjs` — корпус, леммы и зоны;
- `tests/metrics-v5.test.mjs` — TF-IDF, охват, плотность и snapshot-пересчёт;
- `tests/importance-v7.test.mjs` — важность лемм;
- `tests/ngram-importance-v10.test.mjs` — важность N-грамм;
- `tests/stop-presets.test.mjs` — стоп-термы;
- `tests/clouds-v8.test.mjs` и `tests/cloud-layout.test.mjs` — облака;
- `tests/triplets-v9.test.mjs`, `tests/spacy-triplets-v10.test.mjs` и
  `tests/deterministic-triplets-contract.test.mjs` — семантические связи.

Даже после целевых тестов перед PR обязательно запустите полный `npm run check`.

## Snapshot и запрет повторной загрузки

- Текущий контракт — `snapshot v5`. Старый, malformed, пустой или чрезмерный
  snapshot должен отклоняться до обращения к внешнему сервису.
- Пересчёт ключей/стоп-термов и построение семантических связей выполняются только
  из уже сохранённого snapshot. В этих путях запрещены повторный поиск выдачи,
  загрузка страниц конкурентов и Firecrawl fallback.
- Сохраняйте исходный `snapshot.id` при пересчёте. Не подменяйте корпус данными из
  компактных таблиц отчёта: они могут не содержать все термы и предложения.
- Переданный клиентом snapshot остаётся недоверенным: повторно применяйте bounds,
  нормализацию и проверку token/form/count полей. Подделанные `tokenKeys` не могут
  создавать доказательства связей.
- spaCy запускается отдельно и только по явной опции пользователя. Его ошибка
  возвращает типизированную недоступность, но не ломает готовый основной отчёт.
- Любое изменение этих путей обязано сохранить zero-fetch/no-refetch тесты в
  `tests/metrics-v5.test.mjs` и `tests/triplets-v9.test.mjs`.

## Готовность к pull request

Перед передачей изменения:

1. Ограничьте diff задачей и не перезаписывайте чужие несвязанные изменения.
2. Проверьте `git status` и `git diff`; исключите секреты, `.dev.vars`, build
   output, кеши, модели, виртуальные окружения, логи и большие бинарные файлы.
3. Добавьте или обновите регрессионные тесты для каждого изменения поведения.
4. Обновите пользовательскую документацию и `CHANGELOG.md`, если изменились
   установка, конфигурация, API, метрики или видимое поведение.
5. Выполните `npm run check` из корня и устраните ошибки до PR.
6. Для изменений spaCy дополнительно запустите релевантный fixture/diagnostic из
   `services/triplets-symbolic/README.md`; не коммитьте скачанные модели.
7. В описании PR укажите: что изменено, зачем, как проверено, влияние на метрики и
   snapshot/no-refetch, новые переменные/миграции и известные риски.

Изменение готово к PR только когда чисто собирается из свежего `npm ci`, не
требует секретов для базового отчёта, проходит полный check и сохраняет
MIT-уведомления и авторство проекта.
