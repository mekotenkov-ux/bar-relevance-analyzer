# Установка и настройка БАР

Эта инструкция рассчитана на человека без опыта разработки. Она поможет запустить
**БАР — бесплатный анализ релевантности** на своём компьютере и отдельно подключить
необязательные интеграции.

БАР можно использовать в нескольких вариантах:

1. веб-приложение + собственный доступ XMLRiver — основной анализ;
2. Firecrawl — необязательная повторная загрузка страниц, которые не удалось
   нормально получить обычным HTTP-запросом;
3. spaCy — необязательный локальный модуль семантических связей для русского и
   английского языков.

Для обычного отчёта Python, Docker, Firecrawl и spaCy не нужны. Доступ XMLRiver
нужен для автоматического получения конкурентов из поисковой выдачи, но его можно
ввести прямо в интерфейсе и не записывать на сервер.

## 1. Что потребуется

Обязательно:

- 64-битная Windows 10/11, современный Linux или macOS;
- [Node.js](https://nodejs.org/) версии **22.13.0 или новее**;
- npm, который устанавливается вместе с Node.js;
- примерно 1 ГБ свободного места для проекта и JavaScript-зависимостей;
- собственный ID пользователя и ключ [XMLRiver](https://xmlriver.com/), если
  нужно автоматически искать конкурентов.

По желанию:

- [Git](https://git-scm.com/downloads), чтобы клонировать и обновлять проект;
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) или Docker
  Engine с Compose — самый простой способ запустить spaCy;
- Python 3.12 — если spaCy будет запускаться без Docker;
- собственный ключ [Firecrawl](https://www.firecrawl.dev/) для fallback-загрузки.

Проверьте Node.js и npm в PowerShell или терминале:

```text
node --version
npm --version
```

Первая команда должна вывести `v22.13.0` или более новую версию. Если команды не
найдены либо версия старее, установите актуальный Node.js, полностью закройте
терминал и откройте его заново.

## 2. Получение проекта

### Вариант A: через Git

На странице проекта в GitHub нажмите **Code → HTTPS** и скопируйте адрес. Затем
выполните команду, заменив пример адресом этого репозитория:

```text
git clone https://github.com/mekotenkov-ux/bar-relevance-analyzer.git
cd bar-relevance-analyzer
```

### Вариант B: ZIP-архив без Git

1. На странице проекта нажмите **Code → Download ZIP**.
2. Распакуйте архив в обычную папку, например `Документы\bar-relevance-analyzer`.
3. Откройте PowerShell или терминал в распакованной папке.

На Windows проще всего открыть папку в Проводнике, нажать правой кнопкой мыши по
пустому месту и выбрать **Открыть в терминале**.

Все команды ниже нужно выполнять из корня проекта — там, где находятся файлы
`package.json` и `env.example`.

## 3. Базовая установка

Установите зафиксированные версии зависимостей:

```text
npm ci
```

Создайте приватный локальный файл настроек.

Windows PowerShell:

```powershell
Copy-Item env.example .dev.vars
```

Linux или macOS:

```bash
cp env.example .dev.vars
```

Файл `.dev.vars` уже исключён из Git. Не переименовывайте его в `env.example` и
никогда не помещайте реальные ключи в `env.example`.

Для первого запуска можно ничего не менять в `.dev.vars`: данные XMLRiver будут
введены в браузере, а Firecrawl и spaCy останутся выключенными.

## 4. Первый запуск

Запустите режим разработки:

```text
npm run dev
```

Терминал покажет локальный адрес. Обычно интерфейс доступен здесь:

<http://localhost:3000/analyzer>

Если терминал показал другой порт, используйте именно его. Не закрывайте терминал,
пока работаете с БАР. Для остановки нажмите `Ctrl+C`.

### Первый анализ

1. Откройте страницу `/analyzer`.
2. В блоке **Доступ XMLRiver** введите свой ID пользователя и ключ.
3. Укажите запрос поисковой выдачи, поисковую систему, регион и количество
   конкурентов.
4. Вставьте URL своей страницы либо переключитесь на **Вставить текст**.
5. Нажмите **Найти и проанализировать**.

Введённые в интерфейсе данные XMLRiver хранятся в `sessionStorage` браузера только
до закрытия вкладки. Сервер не сохраняет их в базе данных. На общем компьютере
после работы закройте вкладку целиком.

## 5. Настройка XMLRiver

Есть два режима. Для личного компьютера безопаснее начать с режима BYOK через
интерфейс.

### Режим A: ввод в браузере

Оставьте эти строки в `.dev.vars` пустыми:

```dotenv
XMLRIVER_USER=
XMLRIVER_KEY=
```

После запуска раскройте **Доступ XMLRiver** и введите данные. Они будут действовать
только в текущей вкладке.

### Режим B: серверная настройка

Откройте `.dev.vars` в текстовом редакторе и заполните:

```dotenv
XMLRIVER_USER=ваш_id
XMLRIVER_KEY=ваш_ключ
```

Полностью перезапустите БАР после изменения файла: остановите процесс через
`Ctrl+C`, затем снова выполните `npm run dev`.

Этот вариант удобен для частного сервера, но любой пользователь доступного ему
интерфейса сможет выполнять запросы за счёт настроенного ключа. Перед публикацией
БАР в интернет обязательно добавьте авторизацию, квоты и ограничение частоты
запросов.

## 6. Подключение Firecrawl

Firecrawl необязателен. БАР сначала пробует загрузить URL обычным HTTP-запросом и
обращается к Firecrawl только при ошибке либо при обнаружении низкокачественной
антибот-заглушки.

Добавьте свой ключ в корневой `.dev.vars`:

```dotenv
FIRECRAWL_API_KEY=ваш_ключ_firecrawl
```

Перезапустите веб-приложение. В форме станет доступен переключатель **Firecrawl
для недоступных URL**. Если переключатель выключен, Firecrawl не вызывается.

Важно: при fallback-загрузке адрес и содержимое анализируемой страницы
обрабатываются сторонним сервисом Firecrawl. Наличие ключа не гарантирует обход
любой защиты сайта; неподходящая заглушка всё равно может быть исключена из
анализа.

## 7. Семантические связи через spaCy

Этот модуль необязателен и не влияет на основной отчёт. Он поддерживает готовые
лёгкие модели для русского и английского языков. spaCy запускается отдельным
процессом на `127.0.0.1:8092`, а в интерфейсе включается опцией **Семантические
связи**.

Выберите один способ запуска: Docker или нативный Python. Одновременно запускать
оба не нужно.

### Способ A: Docker — рекомендуется

Установите и запустите Docker Desktop либо Docker Engine. Из корня проекта
выполните:

```text
docker compose -f services/triplets-symbolic/docker-compose.yml up --build -d
```

При первом запуске Docker скачает базовый образ и установит модели, поэтому
процесс может занять несколько минут. Проверить состояние можно так.

Windows PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8092/healthz
```

Linux или macOS:

```bash
curl http://127.0.0.1:8092/healthz
```

Ожидается ответ с `"ok": true` и `"engine": "spacy"`.

Посмотреть журнал сервиса:

```text
docker compose -f services/triplets-symbolic/docker-compose.yml logs -f spacy
```

Выйдите из просмотра журнала через `Ctrl+C`. Сам контейнер продолжит работать.
Для полной остановки выполните:

```text
docker compose -f services/triplets-symbolic/docker-compose.yml down
```

### Способ B: Python 3.12 без Docker

Не устанавливайте spaCy в системный Python. Команды ниже создают отдельное
окружение внутри проекта.

Windows PowerShell:

```powershell
py -3.12 -m venv services/triplets-symbolic/.venv
services\triplets-symbolic\.venv\Scripts\python.exe -m pip install -r services/triplets-symbolic/requirements-spacy.txt
node services/triplets-symbolic/start.mjs
```

Linux или macOS:

```bash
python3.12 -m venv services/triplets-symbolic/.venv
services/triplets-symbolic/.venv/bin/python -m pip install -r services/triplets-symbolic/requirements-spacy.txt
node services/triplets-symbolic/start.mjs
```

Последняя команда занимает терминал и должна оставаться запущенной. Откройте
второй терминал в корне проекта и запустите там `npm run dev`. Проверка `healthz`
такая же, как в Docker-варианте. Остановить нативный spaCy можно через `Ctrl+C`.

### Настройки веб-приложения для spaCy

В корневом `.dev.vars` должны быть строки:

```dotenv
TRIPLET_ENGINE=spacy
TRIPLET_SPACY_URL=http://127.0.0.1:8092
TRIPLET_SPACY_TIMEOUT_MS=900000
TRIPLET_SPACY_MAX_REQUEST_CHARACTERS=128000000
```

После их изменения перезапустите БАР. Основной отчёт строится первым. Затем можно
включить опцию семантических связей и запустить этот этап отдельно. Первый запрос
на каждом языке может выполняться дольше, потому что модель загружается в память.

Не публикуйте порт `8092` в интернет. Встроенный spaCy-сервис рассчитан на
локальное loopback-соединение и не имеет собственной авторизации или rate limit.

## 8. Проверка установки

### Веб-приложение

Откройте <http://localhost:3000/analyzer> в браузере. Либо проверьте ответ из
терминала.

Windows PowerShell:

```powershell
(Invoke-WebRequest http://127.0.0.1:3000/analyzer -UseBasicParsing).StatusCode
```

Linux или macOS:

```bash
curl -I http://127.0.0.1:3000/analyzer
```

Нормальный HTTP-код — `200`. Если сервер выбрал другой порт, замените `3000`.

Проверить, увидел ли backend серверные ключи, можно без раскрытия их значений:

Windows PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:3000/api/search-competitors
```

Linux или macOS:

```bash
curl http://127.0.0.1:3000/api/search-competitors
```

Ответ содержит только признаки `serverConfigured` и `firecrawlConfigured`, а не
сами секреты.

### Полная проверка исходников

Перед обновлением или публикацией своей сборки выполните:

```text
npm run check
```

Команда проверяет TypeScript, стиль кода, production-сборку, JavaScript-тесты и
синтаксис Python-модулей. Для полного `npm run check` команда `python` должна
быть доступна в терминале; устанавливать spaCy и его модели для этой проверки не
нужно. Если вы только запускаете основной отчёт, сам Python не требуется.

## 9. Локальный production-запуск

Режим разработки удобен для работы и изменения проекта. Чтобы проверить сборку,
максимально близкую к production, сначала установите зависимости:

```text
npm ci
```

`npm start` не читает `.dev.vars`: этот файл предназначен для локального
Cloudflare/Vite dev-сервера. Для проверки production-режима создайте отдельный
игнорируемый файл настроек.

Windows PowerShell:

```powershell
Copy-Item env.example .env.production.local
```

Linux или macOS:

```bash
cp env.example .env.production.local
```

В `.env.production.local` укажите локальный адрес:

```dotenv
SITE_URL=http://localhost:3000
```

и при необходимости те же серверные XMLRiver, Firecrawl и spaCy-переменные, что
описаны выше. После этого соберите и запустите приложение:

```text
npm run build
npm start
```

Откройте адрес, который напечатал сервер. На настоящем домене задайте полный
публичный HTTPS-адрес, например `SITE_URL=https://bar.example.com`.

На хостинге секреты нужно задавать через панель переменных окружения или secret
manager платформы. Не копируйте `.dev.vars` или `.env.production.local` в
Docker-образ, публичный архив или Git-репозиторий. Конкретные команды
production-развёртывания зависят от выбранного хостинга.

## 10. Обновление установленной копии

Если проект получен через Git:

```text
git pull
npm ci
```

После обновления перезапустите процессы. Если изменилась Docker-конфигурация
spaCy, пересоберите контейнер:

```text
docker compose -f services/triplets-symbolic/docker-compose.yml up --build -d
```

Если проект был скачан ZIP-архивом, сохраните свой `.dev.vars`, скачайте новый
архив и перенесите `.dev.vars` в корень новой копии. Не заменяйте новым архивом
папку вслепую, если в ней есть ваши изменения исходного кода.

## 11. Частые ошибки

### `node` или `npm` не найдены

Node.js не установлен либо терминал был открыт до установки. Установите Node.js
`>=22.13.0`, закройте все окна терминала и откройте новое.

### PowerShell запрещает запуск `npm.ps1`

Необязательно менять системную политику выполнения. Используйте команды через
`npm.cmd`:

```powershell
npm.cmd ci
npm.cmd run dev
```

### `npm ci` сообщает об ошибке сети

Проверьте интернет, VPN, proxy и доступ к `registry.npmjs.org`, затем повторите
команду. Не скачивайте случайные готовые папки `node_modules` из интернета.

### `npm ci` сообщает, что lock-файл не совпадает

Убедитесь, что `package.json` и `package-lock.json` взяты из одной версии
репозитория. Для неизменённого проекта используйте именно `npm ci`, а не ручную
установку отдельных пакетов.

### Порт веб-приложения занят

Запустите dev-сервер на другом порту:

```text
npm run dev -- --port 3001
```

Затем откройте <http://localhost:3001/analyzer>. При необходимости измените
`SITE_URL` на тот же адрес.

### XMLRiver не подключается

- проверьте ID, ключ, баланс и разрешения в кабинете XMLRiver;
- удалите случайные пробелы до или после значений;
- после изменения `.dev.vars` перезапустите сервер;
- если серверные переменные пусты, раскройте блок **Доступ XMLRiver** и введите
  данные в браузере;
- проверьте, что firewall или proxy разрешает исходящий HTTPS-доступ.

### Переключатель Firecrawl недоступен

Backend не увидел `FIRECRAWL_API_KEY`. Проверьте имя файла `.dev.vars`, имя
переменной и перезапустите БАР. Проверка `/api/search-competitors` должна вернуть
`"firecrawlConfigured": true`.

### Страница исключена как заглушка или бедный контент

Это штатная защита отчёта от антибот-страниц. Подключите Firecrawl и включите его
переключатель. Если это ваша страница, можно выбрать **Вставить текст**. Не стоит
насильно включать в корпус страницу, где вместо содержания действительно пришла
капча или заглушка.

### spaCy показывает `unavailable`

1. Проверьте <http://127.0.0.1:8092/healthz>.
2. Убедитесь, что отдельный процесс или Docker-контейнер запущен.
3. Проверьте `TRIPLET_SPACY_URL` и перезапустите веб-приложение.
4. Для Python-варианта повторите установку через интерпретатор из `.venv`, а не
   через глобальный `pip`.
5. Посмотрите журнал Docker либо сообщение в терминале Python.

Недоступность spaCy не ломает основной анализ: отчёт можно использовать без
семантических связей.

### Docker сообщает, что порт `8092` уже занят

Возможно, spaCy уже запущен нативно или другим контейнером. Сначала откройте
`http://127.0.0.1:8092/healthz`. Если сервис отвечает, второй экземпляр не нужен.

### Анализ слишком долгий или не хватает памяти

- уменьшите количество конкурентов для диагностического запуска;
- временно выключите семантические связи;
- не запускайте много тяжёлых отчётов одновременно;
- для spaCy оставьте таймаут из примера и убедитесь, что у Docker достаточно
  памяти;
- проверьте исходящий интернет и ответы анализируемых сайтов.

## 12. Безопасное хранение ключей

- Никогда не коммитьте `.dev.vars`, `.env` и файлы с реальными credentials.
- Не вставляйте ключи в issue, pull request, скриншоты, публичные логи и команды,
  которые сохраняются в истории терминала.
- Для локальной работы ввод XMLRiver в интерфейсе безопаснее постоянной серверной
  настройки; закройте вкладку после работы.
- Для сервера используйте secret manager платформы, HTTPS, авторизацию, лимиты,
  квоты и отдельный бюджет платных API.
- Не публикуйте локальный spaCy-порт `8092` напрямую.
- Если ключ попал в Git, лог или скриншот, одного удаления файла недостаточно:
  немедленно отзовите ключ в кабинете провайдера и создайте новый.
- Перед commit проверьте `git status` и убедитесь, что `.dev.vars` не включён в
  список изменений.
