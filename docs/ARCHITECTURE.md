# Архитектура БАР

БАР состоит из web-приложения и необязательного локального E5-сервиса.
Основной отчёт остаётся работоспособным без Python, Firecrawl и E5.

```text
браузер
  ├─ подсказки регионов ──> /api/xmlriver-regions ──> полный локальный snapshot XMLRiver
  ├─ поиск конкурентов ──> /api/search-competitors ──> XMLRiver (BYOK)
  └─ запуск анализа ─────> /api/analyze-run
                              ├─ обычная HTTP-загрузка страниц
                              ├─ Firecrawl fallback (BYOK, автоматически при наличии ключа)
                              ├─ локальный E5 на 127.0.0.1:8093 (опционально)
                              └─ расчёт отчёта с детерминированным fallback
                                     └─ snapshot возвращается в браузер
```

## Основные каталоги

- `app/analyzer` — форма анализа и интерактивный отчёт;
- `app/api` — server-side маршруты поиска и основного анализа;
- `lib/semantic-analysis.ts` — загрузка, очистка, морфологическая нормализация, N-граммы,
  зональные метрики и построение snapshot;
- `lib/language-support.ts` — единый реестр языков для backend и UI с явным
  разделением словарной лемматизации, Snowball-стемминга и токенизации без
  склейки словоформ;
- `lib/russian-morphology.ts` — однократная загрузка OpenCorpora-словарей
  Az.Morph и нормализация русских словоформ перед расчётом термов и N-грамм;
- `lib/xmlriver-regions.generated.ts` — gzip-snapshot 99 819 официальных Google
  locations и 708 опубликованных XMLRiver кодов Яндекса; распаковывается один
  раз при старте worker и не требует runtime-сети;
- `lib/xmlriver-regions.ts` — нормализованный список стран и связанная выборка
  городов/регионов по `countryCode`; старое разрешение региона по имени или ID
  сохранено для совместимости;
- `scripts/update-xmlriver-regions.mjs` — проверяемое обновление snapshot с
  сохранением числа строк и SHA-256 официальных исходников;
- `services/phrase-embeddings` — локальный E5-сервис сходства N-грамм с ключами;
- `tests` — контрактные и регрессионные тесты аналитики и интерфейса.

## Границы доверия

URL, HTML, XMLRiver/Firecrawl-ответы и snapshot считаются недоверенными. Прямой
загрузчик ограничивает протокол, порты, redirect и размер ответа, но оператор
публичного self-hosting всё равно должен ограничить сетевой egress и доступ к
private/metadata-сетям на уровне инфраструктуры.

XMLRiver и Firecrawl credentials должны существовать только в runtime. Введённые
в интерфейсе XMLRiver-данные хранятся в `sessionStorage` текущей вкладки. E5 по
умолчанию слушает loopback и не должен публиковаться напрямую.

## Данные отчёта

Серверной базы по умолчанию нет. Каждый запуск возвращает браузеру отчёт и
snapshot корпуса. При подключённом E5 snapshot также хранит ограниченный и
проверяемый кэш оценок для текущих ключей. Позиционные счётчики N-грамм в
snapshot позволяют безопасно отличать самостоятельные фразы от полностью
вложенных без хранения полного корпуса предложений. Позиции считаются только
внутри одного предложения; строка скрывается лишь при одном общем родителе и
полном совпадении этого родителя также на нашей странице. Snapshot нужен для пересчёта
стоп-термов без повторной загрузки конкурентов или повторного E5-инференса.
Интерфейс пытается
сохранить его в `sessionStorage`; это удобство, а не долговременное хранилище.
Ориентиры лемм и N-грамм пересчитываются под объём нашей страницы и каждой зоны,
а взвешенная плотность документов использует те же нормированные под объём цели.
Встроенные стоп-слова выбираются по языку корпуса. Дополнительные редактируемые
пресеты существуют для RU/EN/ES; интерфейс хранит по отдельному черновику на язык.
Автоопределение сначала доверяет корректному `html lang`, затем выбирает
доминирующую письменность и оценивает характерные буквы и локальные стоп-слова
внутри неоднозначной языковой группы. Многословные элементы встроенных
стоп-листов фильтруются только при последовательном совпадении токенов.

## Расширение

Новая аналитическая метрика должна быть детерминированной, иметь понятный
пользовательский смысл и регрессионный тест. Новый язык основного анализа требует
проверки токенизации, фактического режима морфологии, N-грамм и стоп-слов. Внешняя
интеграция должна быть опциональной и не
ломать основной отчёт при отказе.
