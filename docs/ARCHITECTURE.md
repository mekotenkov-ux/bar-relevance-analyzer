# Архитектура БАР

БАР состоит из web-приложения и необязательного локального Python-сервиса.
Основной отчёт остаётся работоспособным без Python, Firecrawl и LLM.

```text
браузер
  ├─ поиск конкурентов ──> /api/search-competitors ──> XMLRiver (BYOK)
  └─ запуск анализа ─────> /api/analyze-run
                              ├─ обычная HTTP-загрузка страниц
                              ├─ Firecrawl fallback (BYOK, опционально)
                              └─ детерминированный расчёт отчёта
                                     └─ snapshot возвращается в браузер

браузер ── отдельная команда ──> /api/analyze-triplets
                                    └─ локальный spaCy HTTP на 127.0.0.1:8092
```

## Основные каталоги

- `app/analyzer` — форма анализа и интерактивный отчёт;
- `app/api` — server-side маршруты поиска, основного анализа и связей;
- `lib/semantic-analysis.ts` — загрузка, очистка, лемматизация, N-граммы,
  зональные метрики и построение snapshot;
- `lib/semantic-triplets.ts` — подготовка корпуса для отдельного этапа связей;
- `services/triplets-symbolic` — детерминированный spaCy-сервис RU/EN;
- `experiments/triplets-llm` и `services/triplets` — архивный LLM-эксперимент;
- `tests` — контрактные и регрессионные тесты аналитики и интерфейса.

## Границы доверия

URL, HTML, XMLRiver/Firecrawl-ответы и snapshot считаются недоверенными. Прямой
загрузчик ограничивает протокол, порты, redirect и размер ответа, но оператор
публичного self-hosting всё равно должен ограничить сетевой egress и доступ к
private/metadata-сетям на уровне инфраструктуры.

XMLRiver и Firecrawl credentials должны существовать только в runtime. Введённые
в интерфейсе XMLRiver-данные хранятся в `sessionStorage` текущей вкладки. spaCy по
умолчанию слушает loopback и не должен публиковаться напрямую.

## Данные отчёта

Серверной базы по умолчанию нет. Каждый запуск возвращает браузеру отчёт и
snapshot корпуса. Snapshot нужен для пересчёта стоп-термов и отдельного запуска
семантических связей без повторной загрузки конкурентов. Интерфейс пытается
сохранить его в `sessionStorage`; это удобство, а не долговременное хранилище.

## Расширение

Новая аналитическая метрика должна быть детерминированной, иметь понятный
пользовательский смысл и регрессионный тест. Новый язык основного анализа требует
проверки токенизации/стемминга; новый язык связей дополнительно требует spaCy-
модели, fixture и ручной оценки качества. Внешняя интеграция должна быть
опциональной и не ломать основной отчёт при отказе.
