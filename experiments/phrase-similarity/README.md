# Пилот сходства фраз: Harrier + E5

Изолированный benchmark сравнивает локальные мультиязычные эмбеддинги и
символьное сходство на коротких формулировках. Он **не подключён к основному
анализатору БАР** и не меняет формулу важности N-грамм.

## Что сравнивается

- [`microsoft/harrier-oss-v1-270m`](https://huggingface.co/microsoft/harrier-oss-v1-270m),
  запрос кодируется штатным prompt `sts_query`;
- [`intfloat/multilingual-e5-large-instruct`](https://huggingface.co/intfloat/multilingual-e5-large-instruct),
  запрос получает инструкцию `Retrieve semantically similar text`, кандидат
  кодируется без инструкции;
- простое среднее двух исходных cosine score — только диагностический вариант;
- среднее двух независимо откалиброванных мнений моделей;
- cosine по счётчикам символьных 2–4-грамм;
- смеси откалиброванного AI-мнения с 10%, 20% и 30% символьного сигнала.

Векторы моделей не складываются: у Harrier и E5 разные размерности и разные
векторные пространства. Усредняются только их скалярные оценки одной пары.

## Тестовый набор

[`fixtures/pairs.csv`](fixtures/pairs.csv) содержит 100 размеченных пар из десяти
независимых групп запросов. Русский — основной срез; дополнительно есть
английский, испанский и немецкий примеры.

Шкала разметки:

| Балл | Смысл |
| ---: | --- |
| `3` | эквивалент, синоним или полноценный парафраз |
| `2` | полезная близкая формулировка или расширение |
| `1` | та же тема, но другой объект либо пользовательский интент |
| `0` | нерелевантная формулировка или лексическая ловушка |

Для бинарных диагностик релевантными считаются баллы `2–3`. Калибровка
выполняется out-of-fold по целым группам запросов: калибратор никогда не видит
тот запрос, который в текущем fold оценивает. Это защищает пилот от утечки между
парами одного запроса.

## Быстрая проверка без моделей

Smoke-режим использует только стандартную библиотеку Python, проверяет число и
контракт строк, группы, распределение меток и символьную метрику. Он не
импортирует `torch`, не обращается к Hugging Face и ничего не скачивает.

```powershell
python experiments/phrase-similarity/benchmark.py --smoke
```

Если команда `python` не зарегистрирована, можно использовать любой локальный
Python 3.12, указав полный путь к исполняемому файлу.

## Полный запуск на CPU

Создайте отдельное окружение, чтобы тяжёлые зависимости эксперимента не попали в
web-приложение или рабочий E5-сервис.

### Windows PowerShell

```powershell
py -3.12 -m venv experiments/phrase-similarity/.venv
experiments/phrase-similarity/.venv/Scripts/python.exe -m pip install -r experiments/phrase-similarity/requirements.txt
experiments/phrase-similarity/.venv/Scripts/python.exe experiments/phrase-similarity/benchmark.py --device cpu
```

### Linux/macOS

```bash
python3.12 -m venv experiments/phrase-similarity/.venv
experiments/phrase-similarity/.venv/bin/python -m pip install -r experiments/phrase-similarity/requirements.txt
experiments/phrase-similarity/.venv/bin/python experiments/phrase-similarity/benchmark.py --device cpu
```

Первый полный запуск скачивает веса моделей. По умолчанию они сохраняются в
игнорируемом каталоге `work/hf-cache`; повторный запуск использует локальный кеш.
Файлы весов занимают примерно 0,54 ГБ для Harrier и 1,12 ГБ для E5, а рабочая
память во время инференса будет выше. Модели обрабатываются последовательно,
поэтому benchmark не обязан держать обе копии весов в RAM одновременно.

Полезные параметры:

```text
--batch-size 16
--threads 8
--max-sequence-length 64
--folds 5
--cache-folder <path>
--results-dir <path>
--harrier-revision <commit>
--e5-revision <commit>
--no-progress
```

### Проверка реальной выгрузки БАР

К полному прогону можно добавить CSV из таблицы N-грамм:

```powershell
experiments/phrase-similarity/.venv/Scripts/python.exe experiments/phrase-similarity/benchmark.py --device cpu --bar-csv "C:\path\to\ngrams.csv"
```

Ожидается стандартный CSV БАР: UTF-8 с BOM, разделитель `;`, обязательные
колонки `Фраза` и `Лучший ключ`. Колонка `Сходство с ключом` необязательна, но
при наличии её старое значение сохраняется для прямого сравнения. Пустые строки
пропускаются, одинаковые пары «лучший ключ + фраза» кодируются один раз.

Пары из CSV объединяются с пилотным набором до инференса. Harrier и E5 всё равно
загружаются только по одному разу, а повторяющиеся тексты внутри общего пула
кодируются один раз. Дополнительный `results/bar-snapshot.csv` содержит исходное
сходство, cosine обеих моделей, их сырое среднее, независимый символьный score и
среднее percentile-мнений внутри каждого лучшего ключа. Percentile не использует
ручные labels и OOF-калибровку пилотного набора.

Для воспроизводимого финального прогона стоит указать commit обеих моделей.
Даже без этого в итоговый JSON записываются разрешённые revision, версии Python,
PyTorch, Transformers и Sentence Transformers.

## Результаты

Игнорируемый каталог `results/` получает два файла:

- `detailed.csv` — каждая исходная пара, fold, все score и место кандидата
  внутри своего запроса для каждого arm;
- `summary.json` — конфигурация, версии, время и память моделей, параметры
  калибровки, агрегированные метрики и разрез по типам пары.
- `bar-snapshot.csv` — появляется только с `--bar-csv`; сравнение старой метрики
  БАР с моделями на реальных фразах.

Основные метрики — `nDCG@5/10`, точность и доля плохих кандидатов в верхней части
выдачи, MRR первого эквивалента, Spearman, PR-AUC и ROC-AUC. Порог в JSON
подбирается на тех же out-of-fold прогнозах только как диагностика. Его нельзя
переносить в production без отдельного, не использованного при настройке набора.
В summary также сохраняются метрики без точных совпадений, отдельные результаты
по языкам (`ru` и общий набор в том числе) и срез `character_trap`: нерелевантные
пары с высокой символьной похожестью либо явной меткой `lexical_trap`.

Сырые cosine разных моделей имеют разные шкалы. Поэтому `ai_raw_mean` нужен для
буквальной проверки гипотезы об обычном среднем, а основным кандидатом является
`ai_calibrated_mean_oof`. Символьный сигнал оставлен отдельным arm и добавляется
к AI только в явно названных экспериментальных смесях.
